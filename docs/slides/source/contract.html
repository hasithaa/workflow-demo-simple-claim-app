Who calls what

Two apps, two APIs. Neither app knows the steps of the process.

AppCallWhat happens
ExpensesPOST /claimsClaims API starts processClaim
ExpensesPOST /claims/{id}/billThe waiting workflow gets the bill
ExpensesGET /claims?employee=…Claims API reads the claims DB
ApprovalsGET /workflow/human-tasksTasks Jane may act on (MANAGER)
ApprovalsPOST /workflow/human-tasks/{id}/completeThe workflow continues with the decision
This is the whole contract between the apps and the integration. Expenses talks to the Claims API we write. Approvals talks to the Management API we get for free. The claim id is also the workflow instance id, so the bill route finds the right waiting workflow directly.
