Both apps are ordinary front-ends with no process logic. The integration we build has two parts. The Claims API starts the workflow and passes it the bill. The processClaim workflow records each step in the claims database, so the portal always shows the current step. The manager console needs no code from us: every human task the workflow creates is available through the Workflow Management API that ships with the runtime. We only turn it on, and the console lists Jane's tasks by role and completes them there. The workflow runs on Temporal, so a claim can wait days for a bill or an approval, across restarts. ICP gives operations the same view: instances, the path each claim took, open tasks.
