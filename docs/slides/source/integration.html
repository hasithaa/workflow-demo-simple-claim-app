What we build in WSO2 Integrator

HTTP service

Claims API

POST /claims

starts processClaim

POST /claims/{id}/bill

sends the bill event

GET /claims

reads the claims DB

Durable workflow

processClaim

1 · Record the claim: BILL_REQUIRED

2 · Wait for the bill (event)

3 · Attach the bill: IN_REVIEW

4 · Ask a MANAGER to approve (task)

5 · Record APPROVED or REJECTED

Built in

Management API

Lists and completes the workflow's human tasks for the caller's role. The Approvals app uses it as is.

enableManagementApi = true

No code: one config value

Three things in one integration. A plain HTTP service, the Claims API, with three resources. The processClaim workflow: five steps, of which two are the interesting ones, waiting for the bill event and asking a manager. Everything else is a database write. And the Workflow Management API, which ships with the runtime and is switched on by config. That is what the Approvals console talks to.
